# המזגנים שלי – שליטה מקומית במזגני Tornado / Hisense

אפליקציה לשליטה במזגנים עם מודול ה-Wi-Fi ‏**Hisense AEH-W4A1**. זה המודול שעובד עם אפליקציית
"AC Control" (`com.accontrol.tornado.america.hisense`).
האפליקציה מדברת עם המזגנים ישירות ברשת הביתית (TCP, פורט 8888), בלי ענן ובלי חשבון.

## מה יש בה
- שליטה מלאה בכל מזגן: הדלקה/כיבוי, טמפרטורה, מצב (קירור/חימום/מאוורר/ייבוש), מהירות מאוורר,
  טורבו, חסכון, נדנוד אנכי/אופקי, תצוגה, מצב שינה. מוצגת גם הטמפרטורה בחדר.
- "כבה הכל" בלחיצה אחת, וכיבוי אוטומטי בעוד 30 דק׳ / שעה / שעתיים / 3 שעות.
- **תזמונים**: שעה קבועה בימים נבחרים, או חד פעמי לפי תאריך (מתאים גם לחגים).
- **שעון שבת**:
  - תזמונים ביחס לכניסת שבת ויציאת שבת, שמחושבים אוטומטית לפי העיר (הדלקת נרות לפי מנהג העיר,
    יציאה בצאת הכוכבים).
  - אשף "תוכנית שבת" שיוצר בלחיצה תוכנית שלמה, למשל: הדלקה חצי שעה לפני שבת, כיבוי ב-02:00,
    הדלקה ב-11:00 וכן הלאה. כל שלב אפשר לערוך.
  - **שמירה על המצב בשבת**: כל 10 דקות השרת בודק שכל מזגן נמצא במצב שהתוכנית קובעת, ומחזיר אותו
    אם צריך. זה מטפל במצב שבו מזגן נכבה בהפסקת חשמל, או שמישהו שינה אותו בשלט.
- חיפוש אוטומטי של מזגנים ברשת, או הוספה ידנית לפי IP.
- יומן פעולות.
- ממשק בעברית שאפשר להתקין על מסך הבית בטלפון (PWA).

## למה האפליקציה המקורית לא מתחברת
1. **המזגן משדר רשת Wi-Fi משלו** (שם כמו `AEH-W4A1-XXXX`), כלומר הוא **לא מחובר** לרשת הביתית.
   מודול במצב כזה מחכה להגדרה, ואי אפשר לשלוט בו מהרשת של הבית. צריך לחבר אותו פעם אחת לראוטר
   (ראו בהמשך). זאת הסיבה הסבירה ביותר לבעיה שתיארת.
2. גילוי המזגנים באפליקציה המקורית מבוסס על הודעות broadcast, וראוטרים רבים חוסמים אותן
   (במיוחד ראוטרי mesh וכאלה שמפרידים בין 2.4GHz ל-5GHz). האפליקציה כאן מתחברת ישירות לכתובת IP
   קבועה, כך שהבעיה הזאת לא קיימת.
3. המודול מטפל רק בחיבור אחד בכל פעם. כשהאפליקציה המקורית פתוחה בכמה טלפונים, החיבורים מתנגשים.
   כאן כל הפקודות עוברות דרך שרת אחד, אחת אחרי השנייה, עם ניסיונות חוזרים.

## איך זה בנוי
דפדפן לא יכול לפתוח חיבור TCP ישיר למזגן, ותזמוני שבת צריכים לרוץ גם כשהטלפון כבוי או לא
מחובר. לכן יש **שרת קטן** שרץ על מכשיר שתמיד דלוק בבית, והאפליקציה בטלפון מדברת איתו.

```
טלפון (אפליקציה בדפדפן)  ⇄  שרת בבית (Python)  ⇄  מזגנים (פורט 8888)
```

השרת כתוב ב-Python ומשתמש רק בספרייה הסטנדרטית, כך שלא צריך להתקין שום חבילה.

## התקנה

### אפשרות א׳: טלפון אנדרואיד ישן שנשאר בבית (מומלץ וזול)
1. מתקינים את **Termux** מ-F-Droid (הגרסה בחנות Play ישנה).
2. ב-Termux:
   ```bash
   pkg install python git
   git clone <כתובת הריפו> && cd test_name/ac-control
   python server.py
   ```
3. בהגדרות האנדרואיד מבטלים את "חיסכון בסוללה" עבור Termux ומשאירים את הטלפון בטעינה.
4. כדי שהשרת יעלה אוטומטית אחרי הפעלה מחדש: מתקינים את **Termux:Boot** ויוצרים את הקובץ
   `~/.termux/boot/ac.sh`:
   ```bash
   #!/data/data/com.termux/files/usr/bin/sh
   termux-wake-lock
   cd ~/test_name/ac-control && python server.py >> ~/ac.log 2>&1
   ```

### אפשרות ב׳: Raspberry Pi או מחשב שתמיד דלוק
```bash
cd ac-control
python3 server.py            # ברירת מחדל: פורט 8080
```
להפעלה אוטומטית בלינוקס אפשר להשתמש ב-systemd או ב-`@reboot` ב-crontab.

### פתיחה בטלפון
גולשים בטלפון לכתובת `http://<IP של השרת>:8080`, ובתפריט הדפדפן בוחרים "הוספה למסך הבית".

## חיבור המזגנים
1. **מחברים כל מזגן פעם אחת לרשת הביתית.** אם המזגן עדיין משדר רשת משלו, מבצעים את תהליך
   ההגדרה של האפליקציה המקורית (חיבור לרשת `AEH-W4A1-...` והזנת סיסמת הראוטר).
   - המודול עובד **רק ב-2.4GHz**. אם הראוטר משדר רשת אחת שמשלבת 2.4GHz ו-5GHz, כדאי לפתוח רשת
     2.4GHz נפרדת לצורך ההגדרה.
2. בראוטר כדאי **לקבוע כתובת IP קבועה** לכל מזגן (DHCP Reservation), כדי שהכתובת לא תשתנה.
3. באפליקציה עוברים ל"הגדרות", לוחצים "חיפוש מזגנים ברשת", ומוסיפים כל מזגן עם שם.
4. מומלץ לא להשתמש באפליקציה המקורית במקביל, כי היא מתנגשת בפקודות.

## אבטחה ושליטה מחוץ לבית
- השרת פתוח לכל מי שמחובר לרשת הביתית. כדי לדרוש קוד גישה מפעילים אותו כך:
  `AC_PIN=1234 python3 server.py`.
- לשליטה מחוץ לבית, הדרך הבטוחה היא [Tailscale](https://tailscale.com) (חינם) על השרת ועל
  הטלפון. **לא** לפתוח את הפורט בראוטר לאינטרנט.

## הערות על שעון השבת
- זמני השבת מחושבים לפי מיקום השמש, ברמת דיוק של בערך דקה. בהגדרות אפשר לבחור עיר, כמה דקות
  לפני השקיעה מדליקים נרות, ואיך מחושבת יציאת השבת.
- "שמירה על המצב" פועלת מ-3 שעות לפני כניסת שבת ועד חצי שעה אחרי צאתה, ורק על תזמונים שמסומנים
  כ"חלק מתוכנית השבת".
- תזמון שהגיע הזמן שלו כשהשרת היה כבוי לא יופעל באיחור של יותר מ-10 דקות. בשבת, כשהשמירה על
  המצב פעילה, המצב הנכון יוחזר בבדיקה הבאה.
- בחגים משתמשים בתזמון "חד פעמי" לתאריך ולשעה.

python3 -m unittest discover -s tests -v        # בדיקות (כולל מזגן מדומה)
python3 tools/fake_ac.py --hosts 127.0.0.2,127.0.0.3   # מזגנים מדומים לניסוי בלי חומרה

הפרוטוקול (XM) מבוסס על המחקר של פרויקט [pyaehw4a1](https://github.com/bannhead/pyaehw4a1),
שמשמש גם את האינטגרציה של Home Assistant. הבדיקות מוודאות שהפקודות שהאפליקציה שולחת זהות
בייט-בבייט לפקודות שנקלטו מהאפליקציה הרשמית.

| קובץ | תפקיד |
|---|---|
| `acctl/protocol.py` | בניית פקודות ופענוח מצב המזגן |
| `acctl/client.py` | תקשורת עם המזגנים, ניסיונות חוזרים, חיפוש ברשת |
| `acctl/zmanim.py` | חישוב כניסת שבת ויציאתה |
| `acctl/schedule.py` | חישוב מתי כל תזמון מופעל |
| `acctl/hub.py` | ניהול מצב, ריענון, הפעלת תזמונים ושמירה על המצב בשבת |
| `server.py` | שרת HTTP ו-API |
| `web/` | האפליקציה (HTML/CSS/JS) |
